## Floating Panels
**Goal:** Replace the fixed Label3D pseudocode board in SortingVR with a reusable, grabbable floating panel that can hold any 2D `Control`, then rebuild the pseudocode display inside it.
#### Architecture I settled on
- **`FloatingPanel`** is a `XRToolsPickable` (inherited from `pickable.tscn`). It holds a `CollisionShape3D` and an `XRToolsViewport2DIn3D` display. It instantiates its own `content_scene` into the display's SubViewport in `_ready`.
- **`PseudocodePanel`** is a `PanelContainer` scene (`MarginContainer` → `VBoxContainer`) that keeps the `set_pseudocode` / `point_at` API and creates one `Label` per line.
- **`SortingBoard`** now exports `pseudocode_panel: FloatingPanel` and reads `panel.content as PseudocodePanel`. It had to change because the content lives in a runtime-instanced SubViewport that no Inspector export can reference.
#### Facts from the XR Tools source
- `let_go` applies the hand's velocity, so drift and inertia come free with `gravity_scale = 0`, damping, and `release_mode = ORIGINAL`.
- The display carries its own `StaticBody3D` on layers 1, 21 and 23. Layer 1 would collide with the panel's own mask, so it should be moved to the Pointable layer only or disabled.
#### Bugs and fixes

|Problem|Cause|Fix|
|---|---|---|
|Assertion that the content wasn't a `PseudocodePanel`|`SortingBoard._ready` ran before the panel's `_ready` (tree order)|`await pseudocode_panel.ready` guarded by `is_node_ready()`|
|`Viewport Texture must be set` error|Probably the addon's scene-level `ViewportTexture` before its late swap (unconfirmed)|Left as likely harmless noise|
|Slider label snapped to handle height|`configure` assigned `Vector3(x, 0, 0)`|Set `name_label.position.x` only|
|Text too dark|The display quad was shaded and lit by room lights|`unshaded = true` on the Display (confirmed working)|
|Content clipped when resizing|Viewport resolution was tied to the panel's size in meters|Separated `resolution` (1152 x 648) from `width` (meters); the height is derived from the aspect ratio|
|Text not filling the panel|Fixed font size|`_fit_text` in `PseudocodePanel`: measure at a reference size, scale by the tighter of the width and height limits, clamp to `max_font_size`, and refit on `resized`|
|Last line clipped|Left out `line_spacing` in the height estimate|Subtract `line_spacing × line count`|
|Last line had a smaller font|`_fit_text()` was inside the label-creation loop|Move `_fit_text()` and `point_at(-1)` to after the loop (your latest message; not yet confirmed fixed)|
